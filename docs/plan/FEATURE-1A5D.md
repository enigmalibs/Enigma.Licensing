# FEATURE-1A5D — Icon set filling the frame

**Status:** DONE
**Type:** single-phase
**Branch:** `feature/feature-1a5d-final3-icon-set`
**Run:** feature/2026-11-04-final3-icons-release

## Objective

Replace the application icon with the new set in `C:\Dev\EnigmaLibs\Branding\Apps\final3\licensing`
everywhere the application shows or ships it: the executable and the window/taskbar icon, the `app.ico`
beside the executable (which the MSI uses for its shortcuts and *Installed apps*), the About dialog's image
and the Linux installer's icons.

## Context & constraints

- **The new artwork** is FEATURE-BD63's tile-less drawing (LIC-A2, *Soft* palette: blue `#6A9BF4`, darker
  blue `#4A72C4`, green `#63C77D`) **scaled by 1.1915 and centred, so it fills the frame**: its longest
  side spans 16 to 240 of the 256-unit view box. The 16–32 px frames come from a simplified master
  (`enigma-licensing-small.svg`) with heavier marks. Generated by `Branding/Apps/export.py final3`, as the
  SVGs' header comments say.
- **The new `.ico`** has the same shape as today's: ten 32-bit RGBA PNG frames (16, 20, 24, 32, 40, 48, 64,
  96, 128, 256), each byte for byte the matching `png/enigma-licensing-N.png` (checked while planning:
  22,117 bytes against today's 16,965).
- **Where the icon lives** (unchanged since FEATURE-1ECA / FEATURE-CF21 / FEATURE-F319 / FEATURE-0156 /
  FEATURE-BD63), today the `final2` files byte for byte:
  - `src/Enigma.Licensing.Desktop/Assets/appicon.ico` — `<ApplicationIcon>`, `MainWindow`'s `Icon`, and the
    `app.ico` the csproj copies beside the executable (`TargetPath="app.ico"`), which
    `packaging/windows/buildmsi.ps1` hands Enigma.Msi for the shortcuts and the product icon;
  - `src/Enigma.Licensing.Desktop/Assets/app-256.png` — the About dialog's image, the `.ico`'s 256 frame;
  - `packaging/linux/icons/enigma-licensing-{16,24,32,48,64,96,128,256}.png` — what `install.sh` installs
    (`ICON_SIZES`), each the `.ico` frame of its size.
- `AppIconTests` (desktop suite) compares the output `app.ico` with the asset, so it follows the asset.
- The masters stay in the Branding repository (CLAUDE.md: "A redesign happens in the Branding repository,
  never here"). The source directory is outside the repository and is left in place.

## Steps

1. Copy, byte for byte:
   - `enigma-licensing.ico` → `src/Enigma.Licensing.Desktop/Assets/appicon.ico`;
   - `png/enigma-licensing-256.png` → `src/Enigma.Licensing.Desktop/Assets/app-256.png`;
   - the 16, 24, 32, 48, 64, 96, 128 and 256 PNGs → `packaging/linux/icons/`.
2. Update the prose that names the icon's source set (CLAUDE.md's icon section and layout line), not the
   historical release notes or completion records.
3. Release build, `AVLN` count, the whole suite, a script check of the frames, and a check that the plain
   publish folder (`packaging/windows/publish.ps1`) — the one the MSI is built from — carries the new
   `app.ico`.

## Acceptance criteria

- The three destinations hold the new files byte for byte (`cmp`), and no old file is left.
- A script check shows ten 32-bit RGBA PNG frames (16 to 256) in `appicon.ico`; `app-256.png` is its 256
  frame byte for byte; each Linux PNG is the `.ico` frame of its size byte for byte.
- The win-x64 publish folder's `app.ico` is the new asset byte for byte.
- The Release build has zero warnings and an `AVLN` count of 0; the whole suite passes (`AppIconTests`
  included) against the run's baseline.
