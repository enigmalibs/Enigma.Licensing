# FEATURE-6D42 — Windows MSI installer

**Status:** TODO

**Branch:** one per phase, see below

## Objective

One command builds the desktop application's Windows installer, exactly as Enigma.GitClient does it
(`FEATURE-EAB7` there): `packaging/windows/buildmsi.ps1` (and a `buildmsi.bat` twin) cleans the
repository, publishes the release, and builds `artifacts/Enigma.Licensing.X.Y.Z.msi` with Enigma.Msi. The
repository carries a copy of Enigma.Msi's worker CLI in `packaging/windows/Enigma.Msi.Worker/`. The MSI is
named **Enigma Licensing**, carries this product line's own upgrade code, and the app's version.

## Context & constraints

- **The reference** is `C:\Dev\EnigmaLibs\Enigma.GitClient`: `packaging/windows/buildmsi.ps1`,
  `buildmsi.bat`, `Enigma.Msi.Worker/` (21 tracked files: 20 build outputs + `README.md`), the
  `.gitignore` entry for `.wixsharp/`, and `WindowsInstallerIdentityTests`. All eight sibling apps that
  ship an MSI vendor the same worker: **Enigma.Msi 1.7.0** (`a7a1bfb`, WixSharp_wix4 2.14.2).
- **The version is the app's own.** GitClient reads `<Version>` from `Directory.Build.props`; here the
  library and the app version independently and `Directory.Build.props` has no `<Version>`. The app's is
  `src/Enigma.Licensing.Desktop/Enigma.Licensing.Desktop.csproj` `<Version>` (2.1.0 today). Enigma.Msi's
  own `buildmsi.ps1` is the family's adaptation for exactly this case: `XmlDocument.Load` of the app csproj,
  `/Project/PropertyGroup/Version`.
- **No MSI of Enigma Licensing exists** (none installed on this machine; the registry's uninstall keys list
  five other Enigma products only). The upgrade code is therefore new, generated once while planning with
  `[guid]::NewGuid()`: `4bad4f52-dd12-4b57-8d94-52fe1936f034` — distinct from the eight siblings' codes.
- **Publish** (FEATURE-11BB): `packaging/windows/publish.ps1` runs `dotnet publish
  src\Enigma.Licensing.Desktop -c Release -r win-x64 -p:PublishReadyToRun=true` and exits with dotnet's
  code. Result: `src\Enigma.Licensing.Desktop\bin\Release\net10.0\win-x64\publish\`, with `app.ico` beside
  `Enigma.Licensing.Desktop.exe` (FEATURE-0156). The native Skia/HarfBuzz `.pdb`s are already trimmed by
  the csproj's `TrimNativeSymbolsFromPublish` target, so this MSI is far smaller than GitClient's.
- **Manufacturer** is `Directory.Build.props` `<Authors>`: "Josué Clément". Windows PowerShell 5.1 reads a
  BOM-less script as ANSI, so the `.ps1` stays ASCII and spells it with `[char]0x00E9`, as GitClient does.
- `.gitignore` ignores `artifacts/`, `*.pdb`, `[Bb]in/`, `[Oo]bj/`, `x64/`, `[Rr]elease/`. No vendored path
  matches any of them — this matters because `git clean -dxf` deletes ignored files.
- `.gitattributes`: `*.dll` / `*.exe` binary, `*.bat` CRLF, everything else LF (the worker's `.exe.config`
  included, as in GitClient).
- **The run may not run `git clean`** in this repository (vibe §5). The script is verified end to end in a
  scratch clone instead. Nothing is installed.
- The WiX CLI is on this machine's `PATH` (`~/.dotnet/tools/wix.exe`), as GitClient's run needed.

## PHASE02 — The buildmsi script

**Branch:** `feature/feature-6d42-phase02-buildmsi-script`
**Status:** TODO

### Steps

1. `packaging/windows/buildmsi.ps1` — GitClient's script, adapted (ASCII, `Set-StrictMode`,
   `$ErrorActionPreference = 'Stop'`, comment-based help):
   1. constants: `$UpgradeCode = '4bad4f52-dd12-4b57-8d94-52fe1936f034'`, `$ProductName = 'Enigma Licensing'`,
      the manufacturer, `$Assembly = 'Enigma.Licensing.Desktop'`;
   2. `git`, `dotnet`, `wix` and the worker checked before anything is cleaned;
   3. the version read from `src\Enigma.Licensing.Desktop\Enigma.Licensing.Desktop.csproj` and checked
      against `^\d+\.\d+\.\d+$`;
   4. `git -C <root> clean -dxf`; 5. `publish.ps1`, then the exe and `app.ico` checked in the publish folder;
   6. the profile written to `artifacts/Enigma.Licensing.X.Y.Z.msipkg.json` (UTF-8 without BOM);
   7. `Enigma.Msi.Worker.exe build <profile>`; its exit code passed on; the MSI's path and the elapsed time
      printed.
2. `packaging/windows/buildmsi.bat` (CRLF): runs `buildmsi.ps1` with `powershell -NoProfile
   -ExecutionPolicy Bypass -File` and passes its exit code on.
3. `tests/Enigma.Licensing.Desktop.UnitTests/WindowsInstallerIdentityTests.cs`: pins the three constant
   lines (upgrade code; product name = `AppInfo.Title`; assembly = the app assembly's name).
4. Docs: `README.md` *Desktop application* (the installer, in prose — the README is packed);
   `docs/RELEASE.md` (an installer step, and why the upgrade code never changes); the `packaging/windows/
   publish.*` headers mention nothing that becomes wrong; CLAUDE.md per the sweep.
5. Verify in a scratch clone: commit the dev's tree there, run `buildmsi.bat`, then read the MSI's
   `Property`, `Directory`, `Shortcut`, `Upgrade`, `Icon` and `File` tables. Also run it with `wix` hidden
   from the `PATH` and check that an untracked canary file survives.

### Acceptance criteria

- In the scratch clone, `buildmsi.bat` exits 0 and leaves `artifacts/Enigma.Licensing.<version>.msi` and its
  `.msipkg.json`; afterwards `git status --porcelain` is empty.
- The MSI's tables show `ProductName` "Enigma Licensing", `Manufacturer` "Josué Clément", `ProductVersion` =
  the app csproj's version, `UpgradeCode` `{4BAD4F52-DD12-4B57-8D94-52FE1936F034}`, `ALLUSERS` 1,
  `ARPPRODUCTICON` set, `INSTALLDIR` "Enigma Licensing" under `ProgramFilesFolder`, and two "Enigma
  Licensing" shortcuts (`DesktopFolder`, `ProgramMenuFolder`) on `[INSTALLDIR]\Enigma.Licensing.Desktop.exe`,
  each with an icon.
- The profile says `"compression": "None"`.
- A missing `wix` stops the script before `git clean`, with the install command in the message.
- The Release build has zero warnings; the whole suite passes, the new test included, against the run's
  baseline.
